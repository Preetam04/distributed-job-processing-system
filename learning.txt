so what's happening in  current flow is that 
when a job is moved from waiting to processing after the worker finishes it's execution it runs the acknowledgement function which checks if the job exists in processing queue with job_id and then removes it. all this is a atomic operation implemented with the help of lua script


the heart beat mechanism
it is used to check if the worker is alive bu updating it's time  after a certain intervals. if the worker is dead the timestamp won't be updated


lease mechanism
so basically each job will be allocated to a particular woker for a lease of 30 sec and lease has to renew each 20 second
if the lease expires it means it was not renewed that means the worker has failed so we have to process that job futher


- Lease is not being remove after the job is removed from processing
    - It was because the acknowledgement function was only removing jobs from the processing queue, we also had to remove the job id from the lease as well



idempotency:
    if a worker finshes a job and crashes before acknowledgement, then we should make sure that the job is not executed twice

gracefull shutdown in recovery 
 we create the timeout function such a that we assign the promises resolve to another vaiable and call that resolve when we get sigterm or sigint flag
